# Hub database role contract

S8 base: `0dc40f7487d0927fd2ffac511f3f063e4246f5d8`. No applied revision is changed.

R7/R6 run `psql -X -v ON_ERROR_STOP=1 -f docs/database-roles.sql` using an operator credential against the explicitly verified database. Install PostGIS as the operator first. The script creates NOLOGIN `map_hub_owner`, restricted NOINHERIT login `map_hub_migrator` (member of owner), and `map_hub_runtime`. It transfers only hub_data object ownership, preserving rows/history and other roles' grants. Set unique login passwords through the deployment secret manager, never command arguments or Git.

For a strictly empty new installation only, revision 0001 executes `CREATE SCHEMA IF NOT EXISTS`, whose PostgreSQL permission check still requires database CREATE even when the operator already created hub_data. The operator temporarily grants CREATE on the verified empty database to map_hub_owner around the first migration invocation and revokes it in a mandatory finalizer, including on failure. Run a second migration after revocation to prove the normal schema-only migrator connection. Never grant this bootstrap capability on an existing GCP database. No revision/history/guard is rewritten. Source: https://github.com/postgres/postgres/blob/REL_17_11/src/backend/commands/schemacmds.c (CreateSchemaCommand checks ACL_CREATE before if_not_exists).

Run the immutable image with entrypoint `python` and command `-m app.db.migrate`, injecting only `HUB_MIGRATION_DATABASE_URL=postgresql+psycopg://…map_hub_migrator…`. Do not inject HUB_DATABASE_URL, provider keys, Redis or encryption secrets. The one-shot job sets `map_hub_owner`, takes an advisory lock, and runs real Alembic revisions through head. Its driver timeout is 10 seconds for locks and 5 minutes per statement; the launcher must also bound total execution to 15 minutes. A duplicate job fails without waiting. Reapply database-roles.sql after migrations to grant the reviewed ACL list. Future objects receive no automatic runtime grants.

Serve with only `HUB_DATABASE_URL=postgresql+psycopg://…map_hub_runtime…`. Startup checks exact shipped Alembic heads, fixed runtime identity, non-elevated role, no owner membership, no database/schema/public CREATE, and expected schema owner before scheduler or providers start. No serving DDL or migration credential fallback exists.

Runtime: region_grid and alembic_version SELECT; subscribed_grids SELECT/UPDATE; forecast/snapshot/place/forbidden-zone tables SELECT/INSERT/UPDATE/DELETE; forbidden_zones_zone_id_seq USAGE only. No subscribed_grids sequence is needed because serving toggles existing rows only. PostGIS public schema USAGE is granted, while existing extension function EXECUTE/type privileges must remain available; no User table access is granted. Preserve current Admin hub_data SELECT during ownership transfer.

R7 cutover: record exact source/image/DB/role/ACL and row/ciphertext fingerprints; quiesce writers; backup; provision and migrate; repeat grants; change only Hub runtime credential; require schema readiness and KMA/PostGIS acceptance; compare fingerprints, accounting for synthetic writes and scheduled collection. Do not run on GCP from R2. Do not downgrade or rewrite history. Since revisions are unchanged, forward recovery normally restores the verified candidate and role config; returning to S8 must retain the restricted runtime DSN (S8 serving does not perform DDL). Never restore an older database over new writes. A failed ownership/migration phase preserves the database for the operator.
